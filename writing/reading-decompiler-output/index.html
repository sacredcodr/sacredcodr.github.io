What a decompiler can actually tell you

reverse engineering

A decompiler gives you a readable reconstruction of a compiled program. It does not necessarily give you the source the author wrote. Comments, abstractions, and other source-level details can be missing, as Hex-Rays explains.

Some names and types may still be available through debug symbols. Microsoft's symbol documentation describes that information. A name you add during analysis has a different origin: it records your interpretation.

Take a name like itemCount

Suppose a value is compared with a loop counter to decide when the loop stops. Renaming it itemCount suggests a purpose that the comparison alone does not establish.

Observed
The value is used in the loop's stopping condition.
Possible
It is a number of items, a capacity, or another limit.
To check
Where the value comes from and how the loop uses it.

This is an illustrative example. The point is to keep a useful guess from becoming an undocumented assumption.

Keep the reason with the name

Possible item count; caller not checked.

A note like this tells the next reader what remains uncertain. Update it when you learn more.
