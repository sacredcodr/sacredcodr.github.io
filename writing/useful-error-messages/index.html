Give the error somewhere to go

Developer tools

A tool stops with Failed to open file. Which file? Was the path wrong, or did the operating system refuse access? The next few minutes depend on information the tool has left out.

Even for someone comfortable with a debugger, a useful error should be readable without opening one.

Keep the context

Consider a hypothetical command-line tool that reads a configuration file. Its first attempt at an error message might be:

Could not load configuration.

If the file wasn't found, a more useful version could say:

Could not open C:/work/tool/settings.json: file not found. Check the path supplied with --config.

The resolved path matters. A relative path such as settings.json leaves the reader guessing which directory the tool used. Naming the failed operation also distinguishes opening the file from reading or parsing its contents.

Don't guess the cause

A failed open does not always mean a missing file. Report the cause available from the underlying operation. If access was denied, preserve that detail. If the tool cannot identify the cause, say so rather than suggesting a fix for a different failure.

The suggested next step should follow from that evidence. Asking someone to check a path makes sense for a missing file. Asking them to reinstall the application gives them a much larger job without explaining why it would help.

What can the reader do next?

A configuration parser can often point to a line and name the value it expected. An unsupported format can identify the formats the tool accepts. An internal failure may need a diagnostic log and a way to report the problem instead.

Keep the first message short enough to read while working. Longer diagnostic details can live in a log or an expandable section. Before asking someone to share that log, check whether it contains private paths, configuration values, or credentials.

During review, deliberately try a missing input file and a malformed configuration. Read only the output the user would see. Can you tell where the operation stopped and choose a reasonable next step? If you need the source code to answer, the message is missing context.
